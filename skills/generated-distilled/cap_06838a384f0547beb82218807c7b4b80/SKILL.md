## review-ui-visual-design

### Guidance

When a user asks you to review an interface they can see (e.g., "看看我这个界面有哪些不好看的地方" or "你觉得有哪些不太好看的地方"), provide structured visual design critique covering:

1. **Most prominent issue first** – Identify the element the user highlighted or the most visually jarring element.
2. **Style consistency** – Evaluate whether icons, illustrations, buttons, and other elements share a coherent visual language (e.g., emoji vs. custom illustration style mismatch, inconsistent proportions, awkward placement).
3. **Layout & spacing** – Note crowding, weak hierarchy, or insufficient visual breathing room in grouped elements (e.g., team info bars, popup layers, button areas).
4. **Typography & button treatment** – Assess whether titles, labels, and buttons look polished or cheap (e.g., heavy borders/shadows, mismatched styling).
5. **Overall direction** – Conclude with a unifying theme for improvement (e.g., "needs a cohesive cartoon classroom style") while affirming that the core functionality or gameplay is sound.

Scope this critique to visual design elements the user can adjust (icons, colors, layout, typography, styling). Do not extend to domain analysis, transcripts, code review, or non-visual concerns. Keep feedback constructive, specific, and actionable.
